version: 0.62.0
headline: A heredoc whose delimiter is split across quotes no longer hides the commands after it from the vault guard
security: true
---

**Affected: every release carrying the heredoc pre-pass, including the fix for
[#973](https://github.com/diazoxide/charter-plane/issues/973). Fixed here.** `cat <<'EO'F` is a
heredoc whose delimiter is `EOF`: a shell removes quotes one character at a time and joins
the pieces, and bash, zsh and dash all end its body at a line reading `EOF`. The guard read
that delimiter as `EO`. No line reads `EO`, so it treated everything to the end of the command
as the reader's body and dropped it, and a `cat .charter/vaults/<v>.json` placed after the
real `EOF` was allowed. `<<"EO"F`, `<<'E'O'F'` and `<<"E""O"F` did the same, in the `<<-`
form too.

The guard already knew the right answer. Bash's own reading of a delimiter was used to end a
`charter handoff` brief, and only a brief, so a reader's heredoc went on using the pattern that
stops at the first quote. Every heredoc body now ends where the shell ends it. A body whose
terminator never arrives is also no longer dropped for any command, not only for a brief,
because a terminator that cannot be found is what a misread delimiter looks like. That refuses
one command it used to allow: a quoted `cat > file <<'X'` that names a vault path and never
reaches its `X`, which bash would also warn about.

Nothing to adopt; the guard updates with the plugin
([#975](https://github.com/diazoxide/charter-plane/issues/975)).
