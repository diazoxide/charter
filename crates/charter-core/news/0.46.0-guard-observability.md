charter's guards could refuse a command and never say which rule matched. One plane's trace
held 335 credential denials in ten days, all recorded as the same fixed label with `cmd` set
to the string `git` — while the guard's own comment claimed it "only catches a deliberate
bypass". Nobody bypasses deliberately 335 times, and there was no way to tell which reading
was right.

A denial now records its **shape**: the trigger that matched, never the operand.

```
{"event": "deny", "reason": "single-credential", "shape": "git GIT_SSH_COMMAND="}
{"event": "deny", "reason": "single-credential", "shape": "git <ssh-url>"}
{"event": "deny", "reason": "single-credential", "shape": "git commit --gpg-sign"}
```

Trigger, not operand, is the whole discipline — this is a guard that exists to keep secrets
out of the transcript, so a trace holding the matched text would rebuild the leak in a file
that outlives the conversation. The same rule closed a leak that was already there: `cmd`
recorded a command's first token, which for `VAR=value git push` is the entire assignment,
value included. It keeps the variable name now.

Nudges gained their other half. charter emitted 231 `ask` decisions in one plane and
recorded nothing about how any of them resolved, so "is this nudge worth its interruptions"
had no evidentiary answer. An approved ask now records `ask-approved`.

## An unattended run no longer stops on charter

A hook `ask` floors the host's decision at a prompt — no permission mode can lift it — so
every nudge charter emitted was an unconditional stop, including in a run launched with
`bypassPermissions` precisely to avoid them. And charter's own injected guidance told the
agent to open a quiz, which hangs just as hard.

Under `bypassPermissions` charter now allows what it would have asked (recording
`ask-unattended`, so the nudge is still counted) and tells the agent to decide and write
down the assumption instead of asking. **`bypassPermissions` means stop asking me, not stop
knowing things** — every `deny` still denies, and the mode is read from the host's own
`permission_mode` rather than a charter flag that could drift from it.

One exception: a run with no workspace is told to stop. Every other nudge names a
preference; that one names a missing input, and guessing it claims somebody else's job for
the whole session.

## `charter guard allow`

The mirror of `charter guard ask`, which had none — charter could make a command prompt more
and never less.

```bash
charter guard allow 'git status *'
```

Writes each harness's own rule, in its own syntax, in the plane's committed settings —
ADR 0014, same as `guard ask`. Your own guards are untouched: an allow rule relaxes the
*host's* prompt, never charter's secret, credential or plane-root denials.

## Also

`trace` now resolves the session id through `charter.session` like everything else. It read
`CLAUDE_CODE_SESSION_ID` directly, so on a harness setting only the neutral
`CHARTER_SESSION_ID` every trace line landed in one shared bucket.
