A persona is edited in `personas/<name>/persona.md`. The sub-agent that gets dispatched reads
`.claude/agents/<name>.md`, which `charter persona sync-agents` generates. Both are committed,
and until now nothing asserted they agreed.

They didn't. On charter's own plane all five were **four days behind** — `release.md` was
missing the guidance about bounded release bodies in the same week an over-long release body
was the blocking defect. A drifted agent file does not fail. It silently runs an older
charter, and reports success while doing it.

**Two things drift, and only one of them is visible by reading.** The persona source moving
ahead of its copy is the obvious half. The other half is charter itself: two of the five files
on this plane were stale because the *generator* had been corrected — a `uses:` sentence
rewritten to say that not opening another persona's vault is a rule you keep rather than a
wall charter holds, and an MCP block whose YAML shape changed when #453 closed. Neither shows
up in a diff between the two committed files, so the check regenerates instead of comparing:
the property is *this file is what `sync-agents` would write today*.

`persona lint` had been saying so all along — and saying it as a **warning**, so `lint` exits
0 and nobody's CI ran it anyway. Noticing without failing is how a guard gets waved through.
The new check has an exit code, and its failure prints the command to run.

## Regenerating no longer writes into a tree you didn't ask for

`charter persona sync-agents` resolved the plane from config rather than from where it was
called, so run inside a linked worktree it wrote `.claude/agents/` into the **main clone** —
a tree the caller does not own, and under parallel work may not know is being used. Charter
tells every worker never to run git in another worktree; this reached out of the caller's
worktree and edited tracked files in the shared clone from underneath that rule.

The fix is not a different root. It is a line that had never been drawn:

- **Identity and machine-local state follow the PLANE** — the persona roster, the vault, the
  MCP approval record, memory, workspaces. A worktree is a view of a plane's repo, not a
  second plane, so none of that may fork per worktree. `root._plane_of`'s redirect is right
  and is unchanged; `charter persona lint` still answers for the plane, which is what an
  adoption probe has to ask about.
- **A generation follows the TREE** — tracked files in, tracked files out. The artifact
  belongs to the commit and the commit belongs to the branch, so `sync-agents` reads the
  sources in the checkout it was run from and writes the outputs beside them. It says where
  it wrote when that is not the plane, and the plane's copy updates when the branch merges.

Reading the sources from the tree is the half that matters most. Moving only the *output*
would have rendered the plane's personas over the branch's own edits — and the author would
have committed the reversion.

`$CHARTER_ROOT=<worktree>` was the workaround. It still works, and it is no longer needed;
unlike the workaround, the fix keeps the plane's MCP approvals in play, so a persona's
credential hand-off is not silently dropped from a generated agent produced on a branch.
