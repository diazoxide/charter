headline: `charter doctor` names a `workspaces/` or a workspace it cannot read, instead of ending in a traceback
---

With `workspaces/` at mode 111, or one workspace directory at mode 000, `charter doctor`
printed a traceback and no rows at all:

```
  File ".../charter/gitpolicy.py", line 219, in scan
    for ws in sorted(Path(workspaces_dir).iterdir()):
PermissionError: [Errno 13] Permission denied: '.../workspaces'
```

The `git auth` check runs fourth. It listed `workspaces/` and each workspace without a
guard, so the error ended the whole command. Every row after it went unreported, and a
doctor that exists to tell you what is broken went down on exactly that kind of problem.

Now the row names what it could not read and what clears it, and every later row reports:

```
  !  git auth          token-only across 1 repo(s); workspaces/ cannot be checked
        → workspaces/ cannot be checked — restoring read access to it clears this.
```

One unreadable workspace is named on its own. The other workspaces' clones are still
checked. A workspace that is a symlink loop is told to fix the loop, since no permission
bit clears one. On Python 3.11–3.13 the `memory indexes` row raised over the same
workspace next, and it no longer does.

`charter git-policy` reads the same scan. Once the scan stopped raising, it would have
skipped the clones it never reached without a word, down to "No git repos found". It now
warns about each directory it could not read, with the same remedy as `doctor`.

Nothing to adopt ([#987](https://github.com/diazoxide/charter-plane/issues/987), [#976](https://github.com/diazoxide/charter-plane/issues/976)).
