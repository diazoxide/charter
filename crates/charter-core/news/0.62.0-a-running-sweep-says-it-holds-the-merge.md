---
version: 0.62.0
headline: The deletion sweep says survivors do not fail it, and no longer says it blocks nothing
---

Two sentences told a contributor that the deletion sweep cannot stop them:

```
gate: reporting only — nothing here blocks. Pass --enforce to make it.
This check reports and blocks nothing. The run summary has the table.
```

They were true about the verdict: without `--enforce`, survivors do not fail the check.
They were false about merging, and merging is what they are read for. The branch policy
waits for every check to *complete*. On PR #982, with the sweep's one shard still running
and every other check green, the merge was refused. It went through once the shard
finished, with the verdict unchanged. The 0.54.0 note, *nothing here blocks a merge*, was
wrong in the same way.

The two facts are now stated separately:

```
gate: survivors do not fail this run. Pass --enforce to make them.
This check never fails on survivors — but it must COMPLETE before the branch policy will let a pull request merge. The run summary has the table.
```

A running sweep is something to wait for, not a failure risk. `CONTRIBUTING.md`'s
*Sweeping the guards your branch adds* now says both.
