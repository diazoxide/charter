headline: A reopen always lands you somewhere, and every other refusal on the quit path now has a test

#810's largest group: **45 branches whose working half is well tested and whose refusal was
only ever the branch not taken.** Every case in the quit/close/reopen suite drove the good
path with a well-formed fixture, so the gates never had anything to refuse.

The remedy is **fixtures that lie**, not tests that assert more. It is the same finding the
release before this one recorded one level down, where five survivors turned out to be one
fixture that wrote a truthy value into every field a fallback could read. Here it is one
level out: the fixture gets past every gate, so no gate has anything to refuse.

## The one that is a real promise: where a reopen puts you

`charter reopen` picks the chat it drops you on with a four-rung ladder — the `active` chat
of the workspace the quit ran from, then the first chat of that workspace, then the first
`active` chat anywhere, then the first chat that came back at all. Each rung is one step
further from *where you were*, and **the point is that none of them is nowhere**: without
the last one, the attach would have no session to name and you would land on whichever
window tmux happened to make current, which is an answer nobody chose.

Every existing case had an `active` chat in the focus workspace. Rung 1 answered every time,
and rungs 2, 3 and 4 were dead code as far as the suite could tell. All four are now driven
by the plane state that reaches them — a focus workspace that came back with nothing marked
active, a focus workspace that did not come back at all, and a plane where nothing matches
either — and each is measured by the two things the operator actually sees: which tmux
session charter attaches to, and which pane it selects first.

Two more on the same path: a chat whose pane record charter cannot use still gets you your
terminal (the `select-window` is skipped, the attach is not), and a workspace with a dot in
its name is attached as `api_2` rather than `api.2`, because tmux reads a dotted `-t` as
`window.pane`.

## The rest, by what each one now promises

- a chat with **no recorded workspace** is stopped and honestly not recorded — writing it
  would put a line in the manifest that every reader discards;
- a **pane record charter cannot use** captures nothing, rather than capturing whatever
  pane `%1` belongs to now;
- `chat: close` typed **outside a frame with no argument** says so in the sentence that
  names the problem, instead of falling through to *"'' cannot name a chat"*;
- closing **the chat you are in** says nothing on a screen that is about to be killed, and
  closing a sibling keeps the sentence;
- forgetting a transcript leaves a manifest that **does not name that chat** exactly as it
  was, byte for byte — rewriting it would replace the file with charter's reading of it;
- a reopen tells you when it **fell back**: a harness this charter cannot launch, a
  directory that has gone, a workspace that is missing, a chat that comes back empty — and
  says nothing when nothing fell back, which is the half no fixture had ever rendered;
- a plane whose `charter.toml` declares **no `[harness]` table at all** is a refusal rather
  than an `AttributeError`;
- `plane_chats` skips a directory an older charter made, and a **loose file** in the frame
  root shaped like a chat id — a name that would otherwise reach a tmux target;
- a chat that names no workspace **sorts last**, as the leftovers it is;
- and `charter frame-close` accepts `" alpha.1 "` — a `--chat-id` tmux expanded with
  whitespace around it is still that chat, and `lstrip` would have refused it as a name.

## Two survivors that no test can close, and what was done about each

**`rec.persona and persona_mod.valid_name(rec.persona)` — the first conjunct is deleted.**
`persona.valid_name` is total: measured on this tree it answers `False` for `""`, `None`,
`0` and `[]` without raising, so `rec.persona and` could only ever restate what the call was
about to say. That is the same finding `persona.set_active` already records about its own
`(name or "")`, and it is the shape this repository deletes rather than documents.

**`not out.stdout.strip()` → `not out.stdout.lstrip()` is the same program.** `s.strip()` is
empty if and only if `s.lstrip()` is empty — the only string either can empty is one that is
all whitespace — so inside a truthiness test the mutation asks nothing and no honest test can
redden it. This is exactly the case the sweep's own `indistinguishable()` exists for (*"a
survivor no test can kill is a false positive, and the place to fix a false positive is the
question, not the answer"*), and it is reported rather than papered over with a test that
would pass either way.

## Verification

57 cases, no tmux — the whole group reproduces on directories. Every one of the 45 was
verified by hand with the sweep's own mutation applied one at a time: **54 mutations** across
`commands_frame.py`, `frame/leave.py`, `frame/reopen.py` and `frame/state.py`, **53 killed**
and one survivor — the `strip` pair above, which is the same program. Two more were dropped
because the line they were about no longer exists (the deleted conjunct). Eleven survived the
first draft and each named a real gap in the fixture — a case that asserted through a reader which
refuses the same value the writer does, a manifest read back through a function that drops
the empty frame it was about to prove, a workspace ordering that happened to agree with the
chat ordinals. Every one of those is now a case whose fixture disagrees on purpose.

## And two survivors nobody had named

#810's own author warned that a survivor list is *a union across runs, not a snapshot*, so
the sweep's operators were re-run over these functions on today's file rather than the
issue's list being worked as gospel. **116 mutations over the 30 functions groups A and B
are about**, and two of them were survivors the issue never mentions:

- **`.decode("utf-8", "ignore")` on the transcript cut.** The byte cut is taken from the
  end, so the only edge it can land inside is the leading one — and every existing case
  builds its capture out of characters whose byte length divides the cap evenly, so the cut
  always landed on a boundary and the handler was never read. A capture one byte off that
  boundary now pins it: the partial character is dropped rather than written as a `U+FFFD`
  the pager would show as noise.
- **`state.record_cwd`'s `if d is None` guard.** #810 named this function's `except OSError`
  and not the refusal two lines above it. The value is a chat id off the manifest, and what
  it records is the directory a later reopen will `os.chdir` into.

With both closed, those 116 mutations leave **one** survivor: the `strip` pair above, which
is the same program.

Nothing to adopt.
