version: 0.62.0
headline: `git commit -F - <<'MSG'` is no longer refused for a message that mentions where charter keeps its vaults
---

The vault guard read the body of `git commit -F - <<'MSG'` as commands, because `git` is not a
program that prints files. A message holding one apostrophe beside a vault path, or a line
opening with a word like `cat` or `less`, was refused as a read of that path. The same message
fed to `cat` went through. A commit message about charter's own layout is ordinary in a plane,
and the workaround was writing the message to a file with another tool.

The quoted body of `git commit -F -`, `-F-`, `--file=-` or `--file -` is now data, as a
`cat` heredoc's body is, with git's global options such as `-C <path>` and `-c key=value`
allowed before `commit`. It stays visible to the guard when the heredoc is unquoted, because a
`$( … )` in it runs; when a shell is anywhere in its pipeline (`… | bash`); and when the
command asks for the editor in any spelling (`-e`, `--edit`, `--edi`, `-ae`), because git hands
the message to the editor and an editor of `sh` runs it. Other spellings, such as `git tag -F -`,
an alias or `-aF -`, keep the body visible as before.

The handoff gate gains from the same change. Its look inside a later `eval '…'` or
`bash -c '…'` was skipped when a commit message with an apostrophe made the call unreadable,
and now it happens.

Nothing to adopt; the guard updates with the plugin
([#997](https://github.com/diazoxide/charter-plane/issues/997)).
