---
version: 0.62.0
headline: A structure stamp charter could not write is named instead of reported as added, and a FIFO in its place no longer hangs the status line
---

A workspace's `.charter-structure` stamp records which layout version the workspace is at. When
something other than a regular file stood at that name, charter refused to write the stamp, but
`charter workspace reinit` still printed `added structure v0 → v5`. The workspace still read as
out of date, so the next `reinit` printed the same line again. A FIFO at that name was worse:
reading the stamp opened it and waited for a writer that never came, so `reinit` and every
status-line render in that workspace hung. Git cannot commit a FIFO, so it took a local file, but
one stray file was enough.

Charter now reads the stamp only when it is a regular file, and never through a symlink. A FIFO
is read without waiting. `reinit` names a stamp it could not write and says what clears it:

```
! 'north': .charter-structure could not be written — …/workspaces/north/.charter-structure is not a regular file, and charter never moves existing content; moving it out of the way clears this.
```

A symlink there gets "is a symlink, and charter writes nothing through one; replacing it with a
real file clears this". `reinit` reports the structure version as added only when the stamp
reads current after the write. The workspace stays flagged until the stamp can be written.

Nothing to adopt. Run `charter workspace reinit --all` to see whether any workspace on your plane
has something in its stamp's place ([#1074](https://github.com/diazoxide/charter-plane/issues/1074)).
