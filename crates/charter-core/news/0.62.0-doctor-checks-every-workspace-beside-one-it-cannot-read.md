version: 0.62.0
headline: `charter doctor`'s `memory indexes` and `workspace clones` rows name a workspace they cannot read and still check every other one
---

With one workspace directory at mode 000, two `charter doctor` rows answered for every
workspace at once. On Python 3.14 the `memory indexes` row went green without having read
that workspace's memory:

```
  ✓  memory indexes    3 base(s) consistent
```

On 3.11–3.13 the same row said `not checked`, and so said nothing about any persona's or
other workspace's memory. `workspace clones` said `not checked` on every version, which hid
a clone one workspace over that was behind its upstream.

Now both rows check everything they can read, and name what they could not with what clears
it:

```
  !  memory indexes    2 base(s) consistent; workspaces/alpha/memory cannot be checked
        → workspaces/alpha/memory cannot be checked — restoring read access to it clears this.
  !  workspace clones  1 clone(s) across 1 of 2 workspace(s), none behind; workspaces/alpha cannot be checked
        → workspaces/alpha cannot be checked — restoring read access to it clears this.
```

Every Python version gives the same answer. A memory base that is a symlink loop was also
skipped as absent and counted consistent, and it is now told to fix the loop.

Nothing to adopt ([#1014](https://github.com/diazoxide/charter-plane/issues/1014)).
