version: 0.62.1
headline: `charter recall`, `charter change list` and every other reader of memory or changes name a directory they could not read, where they used to say there was nothing in it
---

A memory directory or a `changes/` charter was not allowed to list looked empty. At mode 000
`charter recall` searched around it and said:

```
• No memories match 'keycloak' across workspace, persona, shared, refs.
```

`charter change list` said `No changes in workspace 'alpha'`, `workspace recall` said the
workspace had no memories yet, and the session briefing counted `0 own`. A search that did not
look read the same as one that found nothing.

Now each names the directory it could not read, in the sentence `charter doctor` already uses,
prints everything it could, and exits 1:

```
✗ workspaces/alpha/memory cannot be checked — restoring read access to it clears this.
• No memories match 'keycloak' across workspace, persona, shared, refs; 1 base(s) not searched — charter could not read them.
```

- `charter recall`, `charter persona recall` and `charter workspace recall` still show what
  the other memory directories hold, and exit 1. `charter recall` also names a `refs/`
  subdirectory it could not tell is one, which it used to leave out.
- `persona optimize` and `workspace optimize` name it, go on to the next directory, and exit 1.
  With `--apply` they do not change anything in a directory they could not list.
- `charter persona show` counts a memory directory or a `refs/` it could not list as `?`,
  still prints the charter, and exits 1. It used to stop before the charter.
- `charter workspace fork` copies what it can read and says what it did not carry —
  `Forked 'alpha' → 'beta' (LOCAL) without the memory charter could not read in 'alpha':`,
  then each path — and exits 1. It used to stop with a charter bug report.
- `charter workspace live --off` changes nothing when it cannot list the workspace's
  `changes/`, and exits 1. It used to untrack the manifest and memory, go LOCAL, and leave the
  change records committed.
- `charter change list` exits 1, as it does for a record it could not read. A landing log
  charter could not read stops `change land` for a member with blockers, and `change show` and
  `change revert` name it and exit 1; `change revert` used to say nothing had landed.
  `charter doctor` names a `changes/` or a landing log beside the changes it did read.
- `charter doctor`'s `memory indexes` row names each memory in a directory at mode 666 (its
  names listed, the files not reachable). It used to call that an index charter will not touch.
- The session briefing shows `? own` and the sentence, not `0 own`.
- `charter docs` leaves README's persona roster as it is, names the directory, and exits 1.
  It used to write `0` memories for that persona.
- Commands that have no partial answer to give, such as `persona dedupe`, `persona stats` and
  `ws todo`, print the sentence and exit 1. They used to report nothing to deduplicate, a
  dormant persona or no open todos.

A name in the sentence has its control characters escaped, so a memory file whose name holds a
newline cannot add a line to the briefing, to stderr or to `charter doctor`. A symlink loop gets
`fix the symlink loop at …` in place of the read-access remedy. The same answer on Python
3.11–3.14.

Nothing to adopt ([#1084](https://github.com/diazoxide/charter-plane/issues/1084)).
