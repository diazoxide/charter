---
version: 0.62.0
headline: `CHARTER_NO_BACKGROUND_CHECKS=1` stops charter checking PyPI and your forge in the background
---

charter keeps two caches warm without being asked. `charter _version-check` asks PyPI whether
a newer charter is published, and `charter gl-refresh` runs `gh` or `glab` over every clone in
the workspace for the CI columns. The status line, the frame's gather and SessionStart start
them whenever a cache is stale. Until now nothing turned them off: an offline machine, a CI
job, or anyone who did not want charter reaching PyPI or their forge unasked had to plant a
cooldown file in `.charter/cache/` by hand, and that file covered only one of the two.

Now one variable stops both:

```bash
export CHARTER_NO_BACKGROUND_CHECKS=1
```

It is on whenever it holds more than whitespace, `0` and `false` included, because a word
charter did not recognise must not read as permission to reach the network. Unset it, or set it
empty, to turn the refreshes back on. With it on, neither refresh starts and neither writes to
`.charter/cache/`. `charter update`, `charter version bump` and `charter gl-refresh` still
reach the network, because you ran them.

`charter version` no longer says `up to date` when nothing was ever checked. With no cached
answer it prints that the question was not checked, and with the switch on it names the switch:

```
• not checked: $CHARTER_NO_BACKGROUND_CHECKS is set, so charter does not ask in the background. `charter update` asks when you run it.
```

charter's own test suite sets the variable for every process it starts. A test that handed a
fresh plane to a real `charter panel`, `charter frame-gather` or `charter hook sessionstart`
used to send a real GET to PyPI from that child, 18 times in one full run.

Nothing to adopt. See [install.md](https://github.com/diazoxide/charter/blob/main/docs/install.md#what-charter-reaches-on-its-own-and-how-to-stop-it)
([#945](https://github.com/diazoxide/charter/issues/945)).
