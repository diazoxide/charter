---
version: 0.62.0
headline: `charter doctor` no longer rewrites opencode's global plugin while it checks the version lock
---

In a terminal whose `charter` differs from the plane's `[charter] version` pin, the `version
lock` row asks the harness you are in how this plane moves, to word its hint. Under opencode
that question was the move: it ran the writer `charter version sync` and `charter update` use,
which regenerates `<opencode config dir>/plugin/charter.ts` when charter wrote it. opencode loads
that file for every project on the machine, so a `charter doctor`, the SessionStart hook
included, created the plugin where there was none, or restamped an older one to the running
charter.

The row now asks without moving. Every harness answers a dry run with the status and sentence
the real move would give, and writes nothing. `charter version sync` and `charter update` still
move the plugin. An older plugin is still reported by `doctor`'s `harness` row, which only ever
read it.

Nothing to adopt ([#1039](https://github.com/diazoxide/charter-plane/issues/1039)).
