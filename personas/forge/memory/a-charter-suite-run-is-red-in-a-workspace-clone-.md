# A charter suite run is red in a WORKSPACE CLONE and in any worktree cut

_2026-09-10 15:05 · persistent_

A charter suite run is red in a WORKSPACE CLONE and in any worktree cut from one, green in the plane root and on CI — filed as #944. Two independent causes: (1) _planeguard._pin_the_suite_to_its_own_tree asks only root.tree_of(config.ROOT, here), and tree_of is narrow by design (main tree must BE the plane) while find_root's _outermost hops the plane one level further out than the clone, so the pin never fires two levels down (#785 fixed one level); root.nested_plane_in (#809) composed with tree_of gives the right answer with no new path arithmetic. (2) test_statusline_crash_guard.RenderNeverCrashesCase renders against the REAL plane but redirects only config.STATE_DIR to a tempdir, so glstate's cooldown lock and cache are always absent and every dir looks stale — it forks gl-refresh for whatever workspace the cwd resolves. It passes at the plane root and on CI only because the workspace resolved there has ZERO repo trees (stale = any([]) is False). NOT caused by an inherited $CHARTER_ROOT: _envguard.unset_all() clears it and util.child_env() rebuilds it from config.ROOT.
