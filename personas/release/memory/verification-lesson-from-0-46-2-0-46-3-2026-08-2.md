Verification lesson from 0.46.2 -> 0.46.3 (2026-08-20): a feature whose promise is about the ENVIRONMENT cannot be verified by unit tests that only exercise the code. 'charter guard allow --local' shipped with 16 green tests asserting the local file was written, was idempotent, did not touch the committed file, and that opencode declined — not one asked whether git would KEEP the file. It did not: charter init's baseline .gitignore lacked /.claude/settings.local.json, and I had checked charter's OWN repo (which has that line by hand at .gitignore:58) and generalised. The bug was that a constant and a real plane disagreed, so the fix's tests assert on the shipped artifacts — the baseline TEXT, a real cmd_init, and a pre-existing .gitignore — never on the constant. General rule: when a feature's value rests on a property of the surrounding environment (gitignored, committed, on PATH, reachable), assert that property against a REAL fresh artifact, and fix it BOTH in the template and at the point of use, or every plane created before the fix stays broken exactly where the feature is reached for.
