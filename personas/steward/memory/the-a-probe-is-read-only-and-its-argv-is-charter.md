# The 'a probe is read-only AND its argv is charter's' invariant has TWO c

_2026-08-21 12:51 · persistent_

The 'a probe is read-only AND its argv is charter's' invariant has TWO clauses, and that is why charter's news check: gate is an allow-list (_PROBEABLE = doctor, news, persona lint) rather than a structural argparse rule. argparse can be asked whether a command takes a pass-through positional; it CANNOT be asked whether a command writes — 'check: update --to X' reaching a real uv tool install has no pass-through positional at all, so a structural rule waves it through. The structural check still exists, moved to CI as a test asserting nothing on the list takes a pass-through positional and everything that does is off it: entries, list and parser ship in ONE wheel, so a test across the three is a proof rather than a sample, and it fails the PR that adds the drift instead of the machine that installs it. Two traps found the same day: 'version' must NOT be listed (it always exits 0, so an entry naming it reports adopted everywhere forever), and argparse READS PAST A FLAG to find a subcommand, so 'news --pending stamp 9.9.9' really reaches cmd_news_stamp — a prefix walk that stops at the first flag scores it as plain 'news' and allows a file rename.
