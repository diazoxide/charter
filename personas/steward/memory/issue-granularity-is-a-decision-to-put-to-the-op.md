ISSUE GRANULARITY IS A DECISION TO PUT TO THE OPERATOR, not one to delegate to the agent doing the filing. On 2026-08-21 an authority audit produced 19 issues in one day — 14 of them in 129 seconds — on a tracker that had ZERO open issues that morning. The operator had ruled on DISCLOSURE (public, mechanism-only) and I never asked about COUNT, so I approved one-issue-per-finding without weighing what the tracker would look like afterwards. Most of #329/#334/#335/#337 were instances of one root cause (#328) closed by a single PR — issues that existed only to be closed together. The concrete cost was not aesthetic: commands_workspace.py:521,526 ended up claimed by THREE tickets, each assuming another covered it, and only a sub-agent's cross-read caught the orphan. A checklist on one issue cannot produce that failure. When the operator was offered consolidation afterwards they chose to leave it (the fix in flight closes five anyway) — so the lesson is about ASKING UP FRONT, not about the cleanup. Ask: one issue per finding, or one root-cause issue with checkboxes?
