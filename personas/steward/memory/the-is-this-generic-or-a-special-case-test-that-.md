The 'is this generic or a special case' test that settled two charter issues on 2026-08-19: a feature is generic if it adds a ROW, not a COLUMN — one entry in a table charter already owns, no new verb/flag/concept. op:// and vault:// are named VENDOR integrations and are still clean by that test, so 'vendor-agnostic' is the WRONG bar. Applied: #277 'read the browser session token' became one _RESOLVERS row (browser://<session>/localstorage/<key>) instead of a 'charter browser token' subcommand, and every consuming path (--env/--file/--dotenv/redaction/persona secret exec) then worked untouched. Ask 'row or column?' before designing any new charter surface.
