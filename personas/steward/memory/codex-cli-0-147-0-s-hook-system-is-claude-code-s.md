# Codex CLI 0.147.0's hook system is Claude Code's contract near-verbatim

_2026-08-17 16:24 · persistent_

Codex CLI 0.147.0's hook system is Claude Code's contract near-verbatim — charter's existing hooks.py may work there almost unchanged. Extracted from an embedded draft-07 JSON schema inside the binary (strings ~/.codex/packages/standalone/releases/<ver>/bin/codex, search '"hook_event_name"'), not from docs. Events: PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, Stop. PostToolUse input requires {cwd, hook_event_name, model, permission_mode, session_id, tool_input, tool_name, tool_response, tool_use_id, transcript_path, turn_id} — same field names as Claude Code plus Codex extensions turn_id/agent_id/agent_type. Output wire: hookSpecificOutput{hookEventName, additionalContext, permissionDecision, permissionDecisionReason, updatedInput, updatedPermissions}, plus continue/stopReason/suppressOutput/systemMessage. Hooks carry a TRUST model (config keys matcher/hooks/enabled/trusted_hash; --dangerously-bypass-hook-trust exists). Env injection point for CHARTER_HARNESS is shell_environment_policy.set. Codex also HAS a status line (TUI keys status_line, status_line_use_colors; /statusline command), so it likely has fewer ceilings than opencode. Still unverified: exact TOML shape for writing hooks + status_line.
