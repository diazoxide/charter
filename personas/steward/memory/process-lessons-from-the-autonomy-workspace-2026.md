Process lessons from the 'autonomy' workspace (2026-08-19/20), earned the hard way across four releases in one day. (1) BATCH RELEASES. 0.46.0->0.46.1->0.46.2->0.46.3 in one day meant three hurried verification passes instead of one careful one, and 0.46.2 shipped BROKEN (--local wrote a file the plane did not gitignore). Caught only by a smoke test I nearly skipped because 16 unit tests were green. Cutting a release per fix is what made each pass shallower. (2) DISPATCH RELEASE WORK TO THE 'release' PERSONA. I did four release cycles as steward while correcting release's memory twice — that persona holds exactly the knowledge that bit me (the PyPI index-lag lie, the five version points, the asset-freshness gate). charter's routing hook said so on turn one. (3) WATCH FOR WORKSPACE DRIFT. 'autonomy' absorbed a permissions-ergonomics feature, a flaky-test fix and a plugin-versioning gap — none of them autonomy. A charter that describes a grab-bag is worse at its only job, telling a fork what the work is. Open a new workspace when the causal chain leaves the vision. (4) The causal chain ITSELF was right to stay in one session: #299 was only findable because the context held WHY the ask became an allow. Split by subject, not by discovery.
