# docs/assets/demo-plane.sh used to run charter init with the caller PATH

_2026-09-11 02:27 · persistent_

docs/assets/demo-plane.sh used to run charter init with the caller PATH and HOME, so with claude on PATH every capture that builds the demo plane ran claude plugin marketplace add and claude plugin install charter@charter --scope project for the throwaway plane: a GitHub fetch and an entry in the operator ~/.claude/plugins/installed_plugins.json (the #958 captures left charter@charter[16] with projectPath .../scratchpad/readme-frame/cap-full/plane, not removed). capture-demo.sh had the same leak (it runs init through a PATH shim with claude still visible); by the #958 round-2 review the operator file held 13 charter@charter entries naming temp dirs. Fixed in #958 rounds 1-2 with ONE sourced helper, docs/assets/isolated-init.sh: isolated_charter_init strips every PATH dir holding an executable claude (plugincache.available is shutil.which("claude")) and puts XDG_CONFIG_HOME on a mktemp dir; demo-plane.sh and capture-demo.sh both call it, so a new capture script must too. PATH, not HOME: an isolated HOME leaves claude findable and init still installs, against an empty config. Cost: frame-full.svg is unchanged (only the animated attention spinner glyph varies run to run), but demo.svg transcript changes on its next re-take: no plugin row, opencode files written fresh (10 items, not 8). Verify no leak by sha256 of ~/.claude/plugins/installed_plugins.json before and after, never by editing it.
