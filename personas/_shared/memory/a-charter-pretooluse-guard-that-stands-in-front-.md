A charter PreToolUse guard that stands in front of a host ask rule (the handoff consent gate A7, PR 972, 2026-09-11) can only be a GOOD-FAITH spelling guard, never a boundary. Claude Code's permissions docs say a Bash rule isn't a security boundary around the program, and charter's guards read argv shape. A reviewer measured on Claude Code 2.1.268, with the rule in place, that a charter handoff ran with NO prompt when its words were spelled through ANSI-C quoting, locale quoting, an empty quote glued inside the word, brace expansion, a parameter default, a glob, eval, or bash -c. An argv guard misses all of those unless told to look. Ruled response (don't chase every shell spelling, and never refuse a mere mention such as grep handoff in charter's own repo): (1) the refusal text and docs say what the guard recognises and list what it cannot see (interpreters, variables, script files, heredoc bodies fed to a shell); (2) refuse when a command's first or second word carries shell quoting, expansion or glob characters and still reads as the command name once those are stripped or glob-matched; (3) look one level into eval and sh or bash -c string arguments; (4) find heredocs from the lexer's bare << operator, never a regex, because a << inside a comment or quotes otherwise hides every later line from every guard. Related: the two memories on Claude Code 2.1.268's host ask rule for charter handoff.
