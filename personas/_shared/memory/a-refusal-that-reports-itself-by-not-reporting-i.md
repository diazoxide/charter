A REFUSAL THAT REPORTS ITSELF BY NOT REPORTING IS INDISTINGUISHABLE FROM A CRASH. charters sweep shard, on a red unmutated baseline, deliberately returned 0 WITHOUT writing its --json result file. The aggregator then saw no artifact, which is the same thing it sees when a shard dies mid-run, and named it "no verdict: 1 of 1 shard did not report" — while both jobs stayed green. I diagnosed this as a naming bug about zero-mutation diffs; that was wrong and the agent proved it against main: a shard file containing [] already gave "nothing to sweep" correctly. The actual defect was that a REFUSAL had no representation at all. Fixed by writing a refusal file the aggregator can read, so it now says "no verdict: 1 shard refused: the baseline is red" and names the failing test. General rule: a component that declines to answer must SAY it declined, in the same channel it would have answered in. Silence is already taken — it means the component died — and a deliberate refusal that borrows it is a bug wearing an outage costume.
