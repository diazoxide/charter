# A SHARED TEMP FILENAME LOSES THE ATOMICITY THE RENAME GIVES YOU. os.repl

_2026-09-04 15:48 · persistent_

A SHARED TEMP FILENAME LOSES THE ATOMICITY THE RENAME GIVES YOU. os.replace is atomic, but if every writer publishes through the SAME temp name (<target>.tmp), two concurrent writers truncate and publish each others half-written file. charter had this at 21 sites — 17 in frame/state.py, gather.save, toolgate.snapshot, workspace._write_manifest — and it surfaced as a ZERO-BYTE gather cache on a CI branch that touched none of that code. The reader made it invisible: gather.cached answers None for both "missing" and "unparseable", so a truncated cache reads as "nothing saved yet". Two of the sites were worse than a redraw: toolgate.snapshot is the per-session tool ceiling and a ceiling read back empty APPROVES NOTHING, and workspace._write_manifest writes a COMMITTED file that git add reads. Fix is a temp name unique per writer (target + pid + os.urandom hex), removed on every failure with except BaseException — not OSError, since an unencodable payload leaves litter too. NOT tempfile.mkstemp: its unconditional 0600 would land on the committed workspace.json. Pin it with a test that actually races (N writers, one target, a reader watching) and verify the test by hand-applying the fixed-name mutation and watching it go red.
