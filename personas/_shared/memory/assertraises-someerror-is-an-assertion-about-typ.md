assertRaises(SomeError) IS AN ASSERTION ABOUT TYPE, AND TYPE IS NOT THE REASON. Measured 2026-08-29 in tools/sweep.py's own argument parser, the eleventh unpinned line found in the tool built to catch this class: parse_shard's refusal could be DELETED OUTRIGHT and every test still passed, because int('') and int('two') raise ValueError too. With the guard: '--shard wants N/M, not 2'. Without it: 'invalid literal for int() with base 10'. Same exception type, different reason — and assertRaises(ValueError) cannot tell them apart. This is #558 exactly (deleting release.yml's -z refusal left the run still exiting 1 because the check below it caught the empty string), reproduced inside the harness built around that finding. Rule: a refusal test asserts WHICH refusal fired, by its message, never by the exception class alone. And when two refusals share a condition, drop each CONJUNCT separately — a whole-condition mutation cannot distinguish them. This is the same family as 'an assertion about absence standing in for one about value' (7 of the first 9 findings): assertRaises asserts the absence of success, not the presence of the right reason.
