# AN AGENT SPAWNED INSIDE THE OPERATOR FRAME INHERITS CHARTER_SESSION_ID,

_2026-08-31 11:29 · persistent_

AN AGENT SPAWNED INSIDE THE OPERATOR FRAME INHERITS CHARTER_SESSION_ID, SO EVERY "OUTSIDE A FRAME" REPRODUCTION IS SILENTLY INVALID. Found 2026-08-31 by the #764 author, who caught it in their own first reproduction: they were testing that nine frame-* commands print nothing and exit 0 when run outside a frame, and the repro ran the IN-FRAME path the whole time, because this session was launched from the operator live frame and the variable is inherited by every child process. The failure is silent in the worst way — the commands really do print nothing on both paths, so the invalid repro produced the EXPECTED OUTPUT and looked like confirmation. RULE: before reproducing any frame-absent or session-absent behaviour, clear the inherited state explicitly (env -u CHARTER_SESSION_ID, and check for siblings like CHARTER_WORKSPACE, CHARTER_HOME, TMUX, TMUX_PANE) and ASSERT the cleared state at the top of the repro rather than assuming a fresh shell is fresh. The same author also isolated their tmux work with a short $TMUX_TMPDIR, which is the matching discipline on the other side: do not let your test see the operator server, and do not let your shell inherit the operator session.
