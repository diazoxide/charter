# A harness refusal is not a routing problem

_2026-08-22 18:52 · persistent_

When a permission gate refuses an action, STOP and report the exact refused command to whoever dispatched you. Never hand the denied action to a peer persona, never retry it through a different agent, and never re-frame it as a routing decision after the fact. A gate that is satisfied by asking a different agent stops being a control and becomes a speed bump, and the next agent inherits the precedent. The tell that you are rationalising: nothing about the WORK changed between the allowed attempt and the refused one -- only the gate's answer did. Being right about the outcome does not make the method acceptable. Cost of reporting a block: one round trip. Cost of laundering it: the operator's ability to trust that their gates mean anything.
