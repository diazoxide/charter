# A writer of a committed file must not follow a per-shell env var (reinit

_2026-09-11 13:11 · persistent_

A WRITER OF A COMMITTED FILE MUST NOT FOLLOW A PER-SHELL ENV VAR, EVEN WHEN THE CHECKER BESIDE IT DOES (controller ruling on PR 970 / #969, 2026-09-11). doctor's plane-root guard row follows $CLAUDE_CONFIG_DIR, because a row reports on the session in front of it. charter reinit (commands._plugin_dispatches_guard -> doctor._plugin_declaring_guard) decides whether to write the guard hook into the plane's COMMITTED .claude/settings.json, which the sessions of every config folder read. When it followed the shell, a second-account shell with no plugin wrote the hook, and every ~/.claude session with the plugin then ran the guard twice. Fix: pass folder=Path.home()/'.claude' explicitly, and keep 'writer and checker share one function' by threading a folder parameter rather than splitting. The cost is a doctor remedy ('-> charter reinit') that writes nothing under a named folder, so the hint must say so and name 'charter doctor --fix' from that shell. Per-profile wiring is designed in harness-profiles task 4. Related ruling: a guard sighting that cannot name its folder (predates the field, relative CLAUDE_CONFIG_DIR) must SAY that, neither green nor 'nothing fired' (ADR 0009); guardseen.folder_standing is the single decider.
