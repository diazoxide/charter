# A NUMBER THAT MOVES WHEN THE THING IT DESCRIBES DOES NOT IS NOT MEASURIN

_2026-09-02 18:49 · persistent_

A NUMBER THAT MOVES WHEN THE THING IT DESCRIBES DOES NOT IS NOT MEASURING THAT THING — the cheapest test for a bogus metric. Concrete case: I claimed merging a stale branch would revert four merged PRs, citing 'git diff --stat origin/main origin/<branch>' showing 2936 deletions incl. another PR's whole test file. TWO dots compares TIPS, so a branch merely BEHIND main shows every file main GAINED as a deletion. A merge applies merge-base..head, so it deletes nothing. THREE dots (origin/main...branch) is the question actually being asked. The tell that beats knowing the flag: re-running two-dot later gave 4023 deletions for a branch that had not changed a byte — main had moved. Before escalating on any metric, RE-RUN IT and see whether it is stable against things that should not affect it. Also: 'git diff --diff-filter=D --name-only origin/main...<branch>' empty is the right pre-merge guard against a PR deleting files it does not own; the two-dot form false-positives on every behind-main branch.

**Three dots is not a complete fix — squash breaks it too.** After #826 was squash-merged, `git diff --stat origin/main...strip-keyboard-on-main` still reported 627 insertions: a squash means the branch's commits are not ancestors of main, so the merge-base predates the squash and the diff describes work that has already landed. Both diff forms answer "what is different", and neither answers "did the content land". **The assertion that actually answers it is grepping `origin/main` for the symbols and files the branch was supposed to add** — ten code markers and four news entries, in that case. Use diff to find deletions you did not intend; use markers to confirm arrival.
