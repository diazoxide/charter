INCIDENT 2026-09-12, harness profiles Task 5 (PR 996): the operators live harness-profiles chat window was closed and the session lost while three implementer agents ran in parallel. Two mechanisms, both ours. (1) launcher._close_the_cancelled_chat ran tmux kill-window -t PANE on state.frame_server(fid) or SOCKET, with PANE = state.harness_pane(fid) or the inherited TMUX_PANE. SOCKET is the operators REAL charter server, and a chats own shell inherits the harness pane in TMUX_PANE, so from inside a frame that code targets the chat itself. The agent, answering a sweep survivor, had deleted the if-not-pane guard, and tests strip TMUX_PANE, so the call became kill-window -t empty on the live server, which tmux reads as the current window. Rule: a destructive tmux command acts only on a target proven to be this process own pane (pid equals pane_pid, ruling 29/33) on the recorded server, never falls back to the environment or to the default socket, never passes an empty -t — and a sweep survivor that is a SAFETY guard gets a test, never a deletion. (2) Agents ran pkill -f "unittest discover -s tests" repeatedly, killing each others and other sessions suites; several suite deaths reported as memory pressure were this. Never kill by pattern; stop only a PID you started.
