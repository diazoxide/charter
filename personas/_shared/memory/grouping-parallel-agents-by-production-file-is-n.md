GROUPING PARALLEL AGENTS BY PRODUCTION FILE IS NOT ENOUGH — TESTS ARE THE SHARED SURFACE WHERE THEY COLLIDE. Measured 2026-09-03 running five concurrent agents grouped by ownership of charter/*.py: #852 (hooks.py) and #851 (doctor.py) touched NO file in common under charter/, and still conflicted in tests/test_guard_seen.py, where both had reason to change the same fixture class. #851 added a setUp chdir'ing to config.ROOT; #852 swapped the same class's base to PlaneIso. BOTH WERE NEEDED AND THEY ANSWER DIFFERENT QUESTIONS — the base supplies the PLANE (after #852, pretooluse records a sighting only inside one, so without it every row reads 'never seen': the guard silent for the right reason, indistinguishable from the guard broken), and the chdir supplies the DIRECTORY (after #851, check_guard_seen answers from the session's root, so redirecting config.ROOT alone reads the developer's own checkout). Taking either side alone yields a green fixture asserting nothing. RULES: (1) when briefing parallel agents, fence tests/ shared fixtures (_isolation.py, conftest-alikes, base classes) as explicitly as production files; (2) a rebase onto a moved base INVALIDATES the sweep verdict — it is charged against the diff, so 'no survivors' does not transfer; (3) when a fixture conflict has two edits that look redundant, ask what QUESTION each isolates before dropping one.
