# A TEST THAT COMPUTES ITS EXPECTATION FROM THE THING UNDER TEST SURVIVES

_2026-08-28 23:20 · persistent_

A TEST THAT COMPUTES ITS EXPECTATION FROM THE THING UNDER TEST SURVIVES ITS OWN MUTATION. Three instances in one branch (#576/#537/#504 cluster, 2026-08-28): one read contain.SEQUENCE_SEPARATOR into its expected value, one computed its fixture from MAX_CONFIG_BYTES, and a third passed WHILE ITS MUTATION WAS APPLIED because a sort three functions upstream produced the same answer either way. All three look like real tests, run, and pass — and pass equally with the code deleted. Fix: pin literals, not constants read back from the module. This is the fixture-coincidence family seen from a new angle: not 'the fixture cannot reach the case' but 'the fixture is derived from the case'. Related and equally important (#621's author): THE SWEEP GATE IS REPORTING-ONLY AND GOES GREEN WITH SURVIVORS UNDER IT — a green gate is not 'no survivors', filed on #617. And mutation testing's boundary, stated by the same agent: it can only ask 'is this line tested', never 'is this the RIGHT line' — an adversarial review after a branch was already green found nine reachable defects mutation testing had passed.
