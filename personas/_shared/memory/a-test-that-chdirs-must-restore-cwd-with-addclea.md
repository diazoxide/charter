A TEST THAT CHDIRS MUST RESTORE CWD WITH addCleanup REGISTERED *AFTER* THE ISOLATION FIXTURE'S — and a leaked cwd masquerades as a version-specific CI split. Cleanups run LIFO, so an addCleanup(os.chdir, os.getcwd()) added in the subclass setUp runs BEFORE the base fixture's rmtree; registered earlier, the runner ends the case standing inside a directory about to be removed and every later os.getcwd() raises. Measured on #823: ~40 errors across NINE UNRELATED MODULES. I first saw the CI as 'fails 3.11 and 3.14, passes 3.12/3.13' and diagnosed an OSError-subclass/errno difference across interpreters. WRONG on both counts: the author's own measurement was that ALL FOUR interpreters failed, so the split I read off the check-runs was a partial view of a run still in flight, not a signal at all. I escalated a diagnosis from a snapshot of CI that had not finished. Rule: a CI split across interpreters with no other version signal is more likely leaked process state (cwd, env, chdir) than a language difference. Check what the failing tests share with the passing run's ORDER before blaming the interpreter.
