A SUBSTRING TEST ON A PROJECT NAME MATCHES RANDOM TEMP DIRECTORY NAMES — AND THE TEST SUITE'S OWN PREFIX. Root cause of #830, which I had misdiagnosed twice. tests/_planeguard.py's _CHARTER_MENTION was re.compile('charter|edm', re.I) with NO word boundary on either side (loose on purpose, so 'env -Scharter doctor' still matches when the name is glued to an option letter). Consequences: (a) tempfile.mkdtemp() drew 'tmpq71ovzj50hedm9za' — three random chars spell 'edm' — roughly 1 name in 8,442, which is the coin that made the SAME COMMIT pass one CI run and fail another; (b) worse and deterministic, tests/_isolation.py names every throwaway plane 'edm-test-...', so the suite's own isolation prefix matches the gate unconditionally. The gate then became the whole verdict because three exits ('cannot lex', 'nesting too deep', 'computed command word') answer 'refuse' without ever reading a command position. Fix: a boundaried word test (?<![\w.-])(?:charter|edm)(?![\w.\-/]) at those three exits — the TRAILING class is what kills 'edm-test-' and 'edm/ran', which no boundary rule on the gate could, since 'edm' in 'edm-test-' is already bounded both sides. GENERAL RULE: before treating a CI split on one commit as a race or an interpreter difference, check whether any generated PATH (tempdir, branch name, worktree path) can contain the token being matched. And never let a loose prefilter become the verdict on the paths that cannot decide.
