PRE-REGISTER THE PREDICTION WHEN A RUN WILL TEST YOUR DIAGNOSIS — it converts an outcome into evidence instead of a story fitted afterwards. Adopted 2026-08-31 by the #710 author, and notable because the SAME agent had earlier built a convincing runaway-to-shard map AFTER the fact, against a dirty working tree, and had to retract it. Before the post-rebase sweep it published the per-shard deal (118 mutations / 1 file / 5 shards), named shard 2 as the expected death because it holds all three measured memory-eaters, and marked shard 3 'genuinely uncertain' WITH THE REASON: two of its own measurements disagreed — a hand-built input terminated in 2 iterations while the full enumeration timed out against the real test module, and it had never established whether that mutant ALLOCATES while looping or merely spins. It also stated in advance what each outcome would mean (1 death = clean evidence for #776, since same code and same runaways with fewer casualties purely because the swept tree was correct). Two things make this work and both are copyable: (1) publish the prediction BEFORE the run, so a wrong one is visible; (2) mark genuine uncertainty as uncertain rather than picking the likely answer — a prediction that hedges everything tests nothing, and one that hedges nothing is a story.
