# TMUX TARGET RESOLUTION IS FULL OF TRAPS AND TWO AGENTS HIT DIFFERENT ONE

TMUX TARGET RESOLUTION IS FULL OF TRAPS AND TWO AGENTS HIT DIFFERENT ONES ON 2026-09-01. Measured facts, both versions (3.7c and the 3.2 floor) unless noted. (1) A BARE -t NAME MATCHES WINDOW NAMES BEFORE SESSIONS, and a name match wins: session ws, current window index 0 named zzz, index 1 named ws.9 -> "-t ws" resolves to INDEX 1. charter names every chat window workspace.ordinal, so a bare -t workspace on charter own server names A CHAT WINDOW, chosen by name matching. A docstring in layout.chat_window_argv claimed it resolves to the session current window; that claim was false and is corrected. (2) new-window -t %PANE FAILS on both versions with "can not specify pane here"; -t @WINDOW reads the id as an INDEX; a dotted session name is #695 again. ONLY -t $SESSION works. (3) show-options for an option NOBODY SET is version-split: rc 1 plus "invalid option:" on 3.7c, rc 0 plus an EMPTY LINE on 3.2 — a reader built on it branches on tmux version. A session option resolves inside a PANE format on both, so read it that way: one call, version-free. (4) display-message -p -c CLIENT #{session_name} answers an EMPTY STRING at the 3.2 floor for a client list-clients shows has moved — a check built on it refuses every switch on old tmux and passes on new. Use list-clients -t TARGET instead. RULE: use -a plus an explicit %pane or @window id everywhere, never a bare name; and never read a tmux option through show-options when a pane format can answer it.
