A PIPELINE THAT ENDS IN grep REPORTS A GREEN SUITE AS A FAILURE — the vacuous-assertion class inverted, and it costs a false RED instead of a false green. Seen 2026-09-01: an agent full suite ran clean (9895 tests, OK) but its background task was reported FAILED, because the command chain ended with grep for FAIL|ERROR lines, which found nothing and exited 1. The harness read that exit code as the run outcome. Same family as the eight vacuous assertions found this session — an ABSENCE being given a truth value nobody intended — but inverted: there, a missing needle silently PASSED forever; here, a missing needle FAILS a run that succeeded. RULE: never let grep be the last command in a verification pipeline whose exit code anything reads. Append `|| true`, or test the runner own exit status explicitly (`set -o pipefail` makes this WORSE, not better), or capture to a file and assert on the summary line. AND THE GENERAL FORM WORTH REMEMBERING: whenever an exit code is derived from whether a SEARCH matched, ask what it means when the search matches nothing — that is the case nobody writes a test for, and it is true half the time by construction.
