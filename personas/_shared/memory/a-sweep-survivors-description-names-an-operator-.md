# A SWEEP SURVIVORS DESCRIPTION NAMES AN OPERATOR, NOT A SITE — ADDRESS IT

_2026-09-05 14:44 · persistent_

A SWEEP SURVIVORS DESCRIPTION NAMES AN OPERATOR, NOT A SITE — ADDRESS IT BY LINE NUMBER OR YOU WILL VERIFY THE WRONG MUTATION. On #904 an agent reported `switch.py sorted->list` as KILLED with a full hand-verification, and CI still called it a survivor. Neither was wrong: switch.py had TWO sorted calls one line apart (139 `return sorted(names)`, 140 `return _by_use(fid, sorted(names))`). It read the survivors description, assumed the site, killed 139, and reported that as evidence about 140. A hand-check aimed at the wrong line is not weak evidence, it is NO evidence, and it reads exactly like a real kill. Always resolve a survivor to file:line before mutating anything. The second half is worth as much: when it then asked whether line 140 was observable at all, the answer was that the ordering only reached an output through a leftover append, and the leftovers were ordered only because workspace.list_workspaces HAPPENS to answer that way — an accident at the call site, not a guarantee where the promise is made. The fix was neither pin-it nor delete-it but MOVE the sort into the function that promises the order. When a survivor is an ordering, ask where the promise lives before deciding it is dead.
