Two guards sharing one parse must FAIL THE SAME WAY, and a 'cannot determine' default belongs LAST, after every cheaper question. charter's leak guard and handoff gate (A7) both read one heredoc plan; the leak guard's unknown was 'keep every body visible' (denies) while A7's was 'drop every body' (sees nothing), so a handoff inside bash <<'EOF' ran with no prompt in 7 shapes. Fixing it by flipping A7's default over-refuses the git commit -m "$(cat <<'EOF'...)" shape. The working shape is a PER-ITEM fallback that asks the decisive question (does anything run this body?) and only then falls back to 'assume the worst'. Putting an 'unparseable, assume the worst' check FIRST re-broke the commit-message case, because that very line leaves a quote open until after the body.
