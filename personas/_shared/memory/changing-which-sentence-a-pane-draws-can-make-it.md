# CHANGING WHICH SENTENCE A PANE DRAWS CAN MAKE ITS NEIGHBOURS' TESTS VACU

_2026-09-03 01:57 · persistent_

CHANGING WHICH SENTENCE A PANE DRAWS CAN MAKE ITS NEIGHBOURS' TESTS VACUOUS — GREP THE NEIGHBOURING LINES' TESTS BEFORE SHIPPING. On #752 a new guard made _empty_lines/_unreadable_lines reachable only with a valid_name, which silently made the tui.sanitize half of their bound UNREACHABLE — their docstrings still argued for it at length, and the two hostile-name tests aimed at them would have kept passing while asserting nothing. Caught only because the author grepped for tests of the ADJACENT lines rather than the changed one. Fix was to retarget those tests onto the branch that is now reachable (_gone_lines) and add a LENGTH bound so the truncate stays observable. GENERAL RULE: when a guard changes WHICH branch a caller reaches, the tests that will go vacuous are the ones for the branches it no longer reaches — they are not in your diff and no tool reports them. Also from that PR: 'swap-synonym' is a real sweep operator (.strip -> .lstrip), and it found a GENUINE defect, not noise — rename read a pin with .strip() while own_workspace did too, so CHARTER_WORKSPACE='alpha ' made the walk repoint a different set than the roster it follows.
