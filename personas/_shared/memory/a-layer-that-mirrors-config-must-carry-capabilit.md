# A LAYER THAT MIRRORS CONFIG MUST CARRY CAPABILITY AND NEVER A GRANT. #86

_2026-09-04 04:32 · persistent_

A LAYER THAT MIRRORS CONFIG MUST CARRY CAPABILITY AND NEVER A GRANT. #868 asked charter to mirror opencode.json into workspaces and guest clones, because opencode genuinely reads it at a repo root and a clone stops seeing the plane copy. The agent refused with evidence: `charter guard allow "npm test *"` writes {"permission":{"bash":{"npm test *":"allow"}}} into <plane>/opencode.json, so mirroring the file puts an allow rule in force in a repo nobody granted it in. claude_code.WORKSPACE_KEYS = ("enabledPlugins","statusLine","env") already refuses exactly this for Claude Code — three keys mirrored, never `permissions`. One mechanism writing into one directory must not answer the grant question two ways for two harnesses. The rule generalises: when deciding what a workspace or clone inherits, ask of each file whether it carries CAPABILITY (skills, agents, plugin enablement, status line) or AUTHORITY (permission grants, allow rules, credentials) — capability travels, authority never does. Pinned mechanically: each harness is asked to write an allow rule into a throwaway root, and the test fails if the layer mirrors a file its own guard wrote to.
