CORRECTION, SHARPER THAN THE LAST ONE — CI HAS TMUX; WHAT IT LACKS IS A PTY IT WILL HAND A CLIENT. I twice recorded that "CI installs no tmux" (wrong), then corrected it to "CI does have tmux" (right but not useful enough). The precise fact, measured 2026-09-02 while building the workspace-open tab: the GitHub runner ships tmux and runs the real-tmux suite (9182 tests, 9 skips, test_frame_tmux_integration appears 104 times in the log) — but there is NO TERMINAL A CLIENT CAN ATTACH TO. So anything needing a live attached client must SKIP on CI, and anything needing only a tmux SERVER runs there fine. An agent believing the coarse version wrote an ASSERT where a SKIP belonged and went red on all four Pythons. THE SAME WRONG SENTENCE IS STILL IN THE REPO — sibling test modules and #793 news entry; left alone to keep a diff scoped, so expect to meet it again. RELATED AND LOAD-BEARING: a detached process with all three streams on /dev/null CAN run new-session -d, split-window, set-option and switch-client -c <tty> — all rc 0 on 3.7c and the 3.2 floor. What it cannot do is attach. And os.get_terminal_size() RAISES with streams on /dev/null, so a frame built that way lays out at the 80x24 fallback and drops every panel unless the size is handed in explicitly.
