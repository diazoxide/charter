# Before treating a charter guard bypass as a SECURITY DISCLOSURE decision

_2026-09-11 13:13 · persistent_

Before treating a charter guard bypass as a SECURITY DISCLOSURE decision (stopping to ask the operator, or keeping it off the public tracker), read docs/hooks.md's own ceiling. The PreToolUse guards read argv shape only, and the page documents their blind spots: interpreters (python3 -c), shell strings (sh -c / bash -c), eval, 'It is not a sandbox' (docs/hooks.md ~69-71, 287, 479, 508 on main a5aa860). On 2026-09-11 the controller nearly escalated vault reads through bash -c, sh -c and python3 -c as an undisclosed bypass; all three were documented. The one novel finding was an inconsistency inside an intended check: a heredoc fed to a shell is read after ';' but not after '&&'. It grants nothing beyond the documented sh -c ceiling, so it went to forge as an ordinary public bug, the same way guard bypasses #429, #474, #547 and #556 were filed. Procedure: measure through the FULL hooks.pretooluse in a tests._isolation.PlaneIso plane (not just _leak_reason; PersonaIso captures stdout, so write decisions to a file); diff the result against the documented ceiling; escalate to the operator only what goes beyond it.
