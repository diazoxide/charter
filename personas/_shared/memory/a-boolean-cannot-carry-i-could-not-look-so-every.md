A BOOLEAN CANNOT CARRY "I COULD NOT LOOK", SO EVERY CALLER GUESSES. charter had eleven sites across seven modules where an empty git-status answer meant both "clean" and "unreadable" (#917/#918). The one that mattered most: commands_workspace._work_at_risk and _worktrees_at_risk return what shutil.rmtree is then handed — an unreadable tree read as "nothing at risk" and the directory was deleted. commands._sync_one used the same empty answer to AUTHORISE a git merge --ff-only into a tree nobody had read. tools/sweep dirty_files built its sandbox from HEAD and measured a tree nobody was looking at. The fix could not be done at the call sites, and the reason is a TYPE: worktree.is_dirty returned bool, and a bool has no room for a third state — it became worktree.dirt. Root asymmetry, measured on git 2.50.1: git status --porcelain SUCCEEDS under a held index.lock, because reading a tree needs no lock, while git add -A fails rc 128 — and commit_push discarded the adds exit status, so the next probes rc 0 read as clean. General rule: when a probe can fail, the RETURN TYPE must be able to say so. A bool or an empty collection silently merges failure into the benign case, and no amount of care at the call site can recover a distinction the type threw away.
