Weaker: None. The change is tests-only — `git diff origin/main...HEAD -- charter/` is empty, so there is no input main denies that this branch allows.

Within the suite, the reverse of "weaker" was checked explicitly, because a retry loop is exactly the shape that can make a test unfailable. Every assertion is byte-identical in strictness: `(_DEAD, 33)` is still the only pass for the exit-code test; the signal-death test still requires the sentinel and still pins that tmux reports an empty status; the argv tests still compare the full recorded argv. Three separate branches were added that FAIL rather than retry — array ran but nothing delivered, pane destroyed instead of kept, pane holding a status with no hook run — and mutations 1-6 confirm each stays red. The one behaviour that got looser is the capability probe, and it got looser in the safe direction: it now takes 3 deaths to declare a capability absent instead of 1, so it SKIPS less than main did, not more.

The `_await_file` -> `_await_text` conversions were the one place a widening could have hidden (waiting for content rather than existence could mask an empty write). Mutation 5 was re-run after that change specifically to confirm a hook writing an empty line still goes red.

## Bypass

No bypass. I could not construct an input on which the branch is weaker than origin/main, and I could not make a real charter regression come back as a skip. The retry is entered only through `_the_array_never_ran`, which ASSERTS dead=="1" AND status=="" — I broke the probe (action `touch`->`true`) specifically to reach the retry with a status present, and got six loud failures naming the held status ('33', '4'), never a skip. The one residual, inherent and equal to main's: for the signal-death test alone, a broken probe is indistinguishable from a void (a signal death legitimately has an empty status), so sabotaging the probe mechanism itself yields a skip there — verified, 1 skip. That requires breaking test-harness code, not charter, and main has the same property since #409. Everything else I tried held: stale probe markers fail loud rather than pass (a pre-existing marker makes `_await_file` return early, then `_await_text` times out and `assertFalse(exists(probe))` fires); pane ids never repeat across trials so the per-pane marker and gate paths cannot collide; `_srv` resolves to OP_SOCKET for the operator class, the same server OP_SOCKET_PATH addresses, so the probe is never armed on the wrong server; `_PROBE_INDEX = 1` collides with `_pane_died_teardown_hook_argv` but no caller arms both — I checked all four call sites and the show-hooks output confirms `[0]`=charter, `[1]`=probe.
