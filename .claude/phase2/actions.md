## Blocking

### 1

The declaration is skin-deep for the one capability that reads the filesystem. `ActionCtx` inherits `_serves` as a CLASS attribute (new in this diff, charter/frame/ctx.py), and `action.SERVES["vault"]` is `_vault`, which takes a snapshot argument and ignores it — it reads the vault registry itself. So an action declaring `touches=()` reaches the full inventory: I ran an action whose `vars(ctx)` was `['fid']` and whose `ctx.vault` raised AttributeError, and it still printed `type(ctx)._serves["vault"](None).names() -> ('prod',)` and `.keys('prod') -> ('api_key',)`. No values — but 'absent, not disabled' and 'an action gets what it declared and not one field more' are false, and `test_an_action_that_did_not_declare_vault_has_no_vault_at_all` plus both exactness tests pass with it open, because all three filter `not n.startswith("_")`. ctx.py's new docstring says the underscore is what stops a component reaching these; it does not. Fix: keep the per-contract table off the ctx class (e.g. a module-level `{class: table}` looked up inside `__getattr__`), so `dir(ctx)` and `type(ctx)` expose no callable, and add the assertion that an undeclared action cannot obtain a VaultInventory by any route out of the object — the existing test only checks the attribute is missing. ### 2

Two concurrent invocations of one action id leak an inflight record, and the frame then reports work that is over for 24 hours. `Invocation._work`'s `finally` calls `inflight.finish(self.id, kind=ACTION)`, which globs, filters, and unlinks `(running or matches)[:1]` — two threads reaching it together both select the same file, so one record survives. Measured 5/5 through `ActionRegistry.invoke` (records during=2, after=1, five runs) and 4/5 isolating `inflight.finish` behind a `threading.Barrier`; sequential finishes correctly go 2 -> 1 -> 0, so it is the concurrency, not the semantics. `frame/panel.py:247` and `frame/slots.py:1134` are the readers that ask `kind=None`, so the leaked record draws `⏳ 1 running` for PRESUMED_DEAD_SECONDS (30 min) and then `⋯ 1 stalled` until PRUNE_SECONDS (24 h). `inflight.start` already returns an opaque token that names exactly one record and `Invocation` discards it; give `inflight.finish` a token form and have the receipt retire its own record. This branch is the first caller that starts and finishes records from many threads of one process, and Task 4's palette makes it two keypresses away.
