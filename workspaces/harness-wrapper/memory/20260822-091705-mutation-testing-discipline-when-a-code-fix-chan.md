# Mutation-testing discipline: when a code fix changes error-handling beha

_2026-08-22 09:17 · persistent_

Mutation-testing discipline: when a code fix changes error-handling behavior (e.g. adding a try/except that swallows an exception a test used to rely on propagating), any mutation-test result recorded BEFORE that fix does not transfer — it must be re-run against the current code, not re-asserted in a report. Concrete case: frame/state.py's bump() got a try/except OSError wrapped around its write body to fix an ENAMETOOLONG raise; that same try/except silently swallowed the FileNotFoundError that test_a_reader_never_sees_a_half_written_version's mutation (deleting tmp.write_text) used to produce, making the test vacuous — version()'s own '0' fallback meant the assertion could never fail regardless of whether bump() wrote anything. Caught by replacing bump()'s whole write body with 'pass' and watching the test stay green. Fix: delete tautological tests rather than reword them again; replace with a test of the property that's actually load-bearing post-fix (here: 'a failed write must leave the PREVIOUS value intact', tested by bumping once, mocking the write call to fail, bumping again, and asserting the value is unchanged — verified by mutating the atomic tmp+replace into a direct write, which turns it red).
