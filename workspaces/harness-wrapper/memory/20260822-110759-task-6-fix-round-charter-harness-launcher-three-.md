Task 6 fix-round (charter <harness> launcher): three tmux-3.7c facts worth remembering for any future tmux-driving code. (1) 'tmux -f conf new-session' only reads conf when that call STARTS the server; a later new-session -f on an already-running server silently ignores it -- verified by hand. (2) A hook action string embedded as TEXT inside a tmux config file needs an OUTER tmux-quote layer around it, and nesting shlex.quote()'s own single-quote escaping inside that outer layer corrupts tmux's parsing; issuing the hook via subprocess.run([...]) as a clean argv list (one tmux-quote layer, not two) avoids this entirely and shlex.quote() then works normally. (3) remain-on-exit keeps a dead pane's SESSION alive with nothing to end it if the pane-died hook was never installed in time (a real race: ~8-10ms window from new-session to set-hook) -- an attach against that session blocks FOREVER, not merely returns early. Fix: query 'display-message -p -t <pane> #{pane_dead}:#{pane_dead_status}' EAGERLY right after installing the hook (before ever calling attach), and finish the hook's own job (record + kill-session) if the pane is already dead by then. All three verified end-to-end with a real tmux via a Python pty (fcntl/termios TIOCSWINSZ needed or tmux refuses 'width too small').
