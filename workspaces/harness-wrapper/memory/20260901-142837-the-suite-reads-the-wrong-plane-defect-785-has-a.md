# The suite-reads-the-wrong-plane defect (#785) has a much smaller false-G

_2026-09-01 14:28 · persistent_

The suite-reads-the-wrong-plane defect (#785) has a much smaller false-GREEN half than it looks. Measured: a full 9761-test run against a plane whose charter.toml was deliberately wrong in 19 values (forge owner, memory posture, default persona, slots, mouse, chrome, six component bg, four keys, a size, update channel, harness default) produced exactly 2 failures — and both were cases that read the committed FILE on purpose. A second pass with the exact operator-vs-committed delta on this machine over 2846 tests in 71 frame/plane modules: 1 failure. So config.FRAME/UPDATE/HARNESS are the only plane dicts, UPDATE+HARNESS are already refused by _planeguard's read guard, and almost nothing else in the suite reads the plane unisolated. Do NOT add FRAME to _GUARDED_SETTINGS: dozens of sites use mock.patch.dict(config.FRAME, ...) and _RefusesToBeRead refuses copy()/keys(), so patch.dict explodes. The right seam is config.in_tree(tree) + root.tree_of(plane, start) at suite boot, and _REAL_ROOT must be WIDENED to hold both roots (not swapped) or #527's spawn hole reopens.
