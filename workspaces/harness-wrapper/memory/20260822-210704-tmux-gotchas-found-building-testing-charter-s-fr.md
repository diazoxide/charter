# tmux gotchas found building/testing charter's frame menu (round 2): (1) 

_2026-08-22 21:07 · persistent_

tmux gotchas found building/testing charter's frame menu (round 2): (1) 'tmux display-menu ...' issued DIRECTLY (subprocess.run or Popen, not fired from a key binding) does not reliably wire itself to a target client's own key input -- confirmed it drew visible text but no keypress from any client could ever select an item; only firing the identical command from a real key binding worked. This is a GENERAL property, not limited to format-string expansion (which was the first thing found broken this way). Integration tests for menu behavior must bind to a throwaway key and press it through a pty, never invoke display-menu directly. (2) 'tmux list-clients -t ""' (empty session target) does NOT report zero clients on real tmux 3.7c -- with a client attached it reports the CURRENT session's client, same as an unscoped query. Don't assume an empty/invalid target degrades to 'nothing found'. (3) A display-menu item NAME starting with '-' does not merely disable that one row (as tmux's own docs suggest, 'shown dim and may not be chosen') -- tmux's own arg parser reads it as an unrecognised FLAG of its own ('unknown flag -X') and refuses the ENTIRE display-menu call, rc 1, no menu opens at all.
