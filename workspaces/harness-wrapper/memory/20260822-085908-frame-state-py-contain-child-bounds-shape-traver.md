frame/state.py: contain.child bounds shape (traversal/separators) but not length — a 5000+ char fid passes containment and then raises OSError ENAMETOOLONG from Path.mkdir, uncaught, straight out of bump()/record_exit(). Fix: wrap mkdir in frame_dir (create path) in try/except OSError -> return None; also wrap the write body (tmp write + os.replace) in bump/record_exit for the separate failure surface where mkdir succeeds but the write fails. Deliberately did NOT add a length cap to frame_id (the minting side) — $CHARTER_SESSION_ID reaches bump() without ever going through frame_id, so a mint-side cap would protect only self-minted ids and give false confidence; the resolve-side guard in frame_dir is the one place every caller's id passes through. Gotcha: on macOS/CPython, Path.mkdir(parents=True) does NOT create parent dirs when the FINAL path component itself is invalid (e.g. too long) — it tries os.mkdir on the full path first and only falls back to creating parents on FileNotFoundError, so a too-long leaf name fails cleanly without leaving a partially-created directory tree.
