version: unreleased
headline: A name ends where the string ends — a trailing newline is no longer admitted by the rule whose job is to refuse it
security: true
---

**Affected: 0.53.0 and earlier. Fixed here.** No name charter has ever minted is affected;
see *Who this refuses that it used to accept* below before assuming this reached you.

`persona.valid_name("evil\n")` returned **True**, and a directory `personas/evil<LF>/`
holding an ordinary `persona.md` resolved, loaded, and was rendered by
`charter persona sync-agents` into a generated sub-agent whose YAML frontmatter carried a
blank line through it and whose `GENERATED by` comment was split across two physical lines
by a path that is one name.

The rule was never wrong. `_NAME_RE` is `^[a-z0-9][a-z0-9._-]*$`, which says what it means.
It was **asked** wrong: in Python `$` matches at the end of the string *or just before a
trailing newline*, and every one of these was asked with `.match`, which anchors only the
front. `re.fullmatch` is the property; `$` is a spelling of it that is right for every
string that does not end in U+000A.

That is measured rather than recalled — a sweep of all 1,114,112 codepoints says the set of
characters Python's `$` treats as "the end" is exactly `{U+000A}`. `\r`, U+2028 LINE
SEPARATOR, U+0085 NEXT LINE and the two ASCII vertical spaces are **not** in it, which is
why this needed no normalisation pass: one codepoint, one word per call site.

**Fifteen call sites in ten files, not the two the report named.** The report listed nine
anchored name rules; the sweep that went looking for a tenth found eleven more anchored
patterns and a tenth name rule the report had missed — `commands_secrets._ENV_NAME_RE`,
which guards the name written into a dotenv file and whose caller does not strip. Every
rule that *admits* a value now asks `fullmatch`: persona names, workspace names, doc
topics, plugin ids and marketplace names, MCP and tool permission rules, both
environment-variable rules, both version rules, forge hostnames and `--since` ages.

**Two were "already correct" only because a caller remembered `.strip()`.** That is a caller
compensating, not a rule being right, and the eleventh caller inherits nothing from it. The
rules are correct on their own now. The strips stay, and for a stated reason: each is
normalising the value that is then **used**, not merely the one that is checked.

One strip did go — the one inside `instance.version_ok`, which made the answer be about a
different string from the one the caller spent. `commands._sync_cmd` calls itself *"the last
gate before a requirement specifier"* and interpolates the raw value into
`charter-cp==<version>`, so a padded pin was approved at the gate and spent unpadded past
it. Reading a pin out of `charter.toml` already strips, so pinned planes are unchanged; what
changed is that the gate now checks the value that is spent.

**Six patterns deliberately keep `.match`, and that is the interesting half.** An
*admitter* answers "is this value acceptable?", and over-matching admits what the rule
exists to refuse. A *detector* answers "is this token a redirection, a duration, a config
key I must account for?", and over-matching makes a guard fire on **more** inputs —
tightening it makes the guard fire on fewer. Measured against the real guards: switching
`hooks._REDIRECT_READ_RE` to `fullmatch` stops the leak guard seeing a vault the shell opens
for `< <vault> true`, and switching `hooks._DURATION_RE` makes `timeout 5<LF> cat <vault>`
name `'5\n'` as the program instead of `cat`. The same `$` is a defect in one and
load-bearing in the other, and a sweep that "finished the job" would have turned six
security guards fail-open — `hooks._REDIRECT_RE`, `_REDIRECT_READ_RE`, `_DURATION_RE`,
`_CONFIG_KEY_RE` and `_GIT_CONFIG_KEY_ENV_RE`, and `toolgate._VERSIONED`. All six are pinned
as detectors, with the measurement attached so the next sweep argues with a test rather than
with a comment.

**Who this refuses that it used to accept.** Only a name ending in a newline — a name no
`charter persona create` could mint, because it enforces this same rule. Every name charter
has ever minted is unaffected. A plane holding such a directory does not lose it silently:
`charter persona list` still shows it and `charter persona lint` still names it, with the
newline written as its escape — `✗ evil\u000a: persona 'evil\u000a' does not
load`. The roster answers *what is on disk*, lint answers *and this one is not a
persona*, and that split is what #498 built. What stops is
`sync-agents` writing a generated agent for it.

The refusal sentence itself needed containing on the way out. `persona.reference_refusal`
interpolated the offending name with a bare `.format`, and while `$` admitted a trailing
newline that branch was simply unreachable for the one character that could write a second
line of it — safe by accident. It goes through `contain.readable` now, like the branch above
it always did.

This is the fifth instance of one root cause this month: a check that matches a spelling
instead of the property it means (#547 a flag's spelling vs its parse, #558 a ref's spelling
vs whether the check ran, #537 cwd looks like a checkout vs where the module loaded from,
#498 a Unicode category list vs "renders as nothing"). So what is pinned is the property and
not the instance: every anchored pattern in the package is **discovered** by the test rather
than listed in it, and each must be classified — admitter, detector, line scanner or
substitution — before the suite is green. A tenth rule added next month is a red test naming
the constant, not a quiet inheritance of the same hole.
