---
version: 0.61.1
headline: `charter workspace reinit` names a `refs` that is a dangling link or a file, and a workspace directory that is a symlink loop
---

A workspace whose `refs` was a symlink to a target that is gone, or a plain file, took
`charter workspace reinit` down with a `FileExistsError`: charter tried to create the `refs/`
directory over a name that was already there. Reinit now writes nothing beneath either,
changes neither, exits 0, and says what it found and what clears it:

```
! 'north': refs/README.md cannot be created — …/workspaces/north/refs is a symlink whose target is not there, and charter writes nothing through it; removing or repointing that link clears this.
! 'north': refs/README.md cannot be created — …/workspaces/north/refs is not a directory, and charter never moves existing content; moving it out of the way clears this.
```

A workspace directory that is itself a symlink loop was misnamed as a permissions problem by
`reinit <name>`, and `reinit --all` skipped it without a word and printed "Up to date — nothing
to do". Both forms now name the loop, and `--all` counts it:

```
✗ workspace 'north' cannot be checked — charter changes nothing it cannot see; fix the symlink loop at …/workspaces/north.
• Applied 0 repair(s) across 0 of 2 workspace(s); 1 could not be checked; the rest were current.
```
