**`charter init` wrote a `statusLine` into `.claude/settings.json` for charter's whole
life, and it does not any more.** A new plane's settings file holds `enabledPlugins`, `env`
and the plane-root guard, and nothing else. Claude Code's footer is yours again — charter
neither fills it nor asks about it.

Three other things go with the key:

* **`statusLine` drops out of what a workspace and a guest clone inherit.** The mirrored
  set is `("enabledPlugins", "env")`. There is nothing of charter's under that key to carry
  sideways, and one you wired yourself stays where you put it, the way `permissions` always
  has.
* **`charter doctor`'s session-layer row for Claude Code has two parts, not three.**
  `settings` and `skills+agents` — the two discovery rules charter has measured. The
  `status line ✓/✗` part answered a question about a key charter no longer writes, so it
  could only ever have answered ✗.
* **The trust condition reads "hooks".** Claude Code still gates hooks *and* the status
  line on the directory being trusted, and that measurement has not moved — but charter
  writes only one of the two now, and the half that matters is unchanged: an untrusted
  directory is a plane-root guard that does not fire.

## Your existing plane keeps its status line

`init` and `reinit` are additive. Neither removes the key, neither rewrites it, and neither
warns about it — a key charter has stopped writing is not thereby a key charter may delete
out of somebody's committed, git-tracked file. So an existing plane's footer goes on
working exactly as it did until its owner takes it out, which is one edit:

```jsonc
// .claude/settings.json — delete this block if you want the footer back
"statusLine": { "type": "command", "command": "charter statusline", ... }
```

Put it back the same way and everything works again, including the part below that this
release costs you.

## `charter statusline` is not going anywhere

The issue asked whether the status line was used for anything other than Claude Code's
footer. Measured, it is:

* **the frame** — `charter claude`'s panels are built out of `statusline.py`'s own
  renderers, and about thirteen of its functions are called per repaint;
* **opencode's `/charter`**, a slash command whose body pipes `echo '{}' | charter
  statusline`, which puts the plane into the agent's own context — something no panel can
  do, because a panel draws to a pane the model never reads;
* **`charter statusline --watch`**, the standing remedy opencode and Codex both carry for
  having no status bar at all.

So the command stays, the module stays, and **nothing the TUI draws moved**. What charter
stopped doing is wiring a footer into a harness that has one.

## What it costs: the frame's context gauge

Claude Code hands `context_window.current_usage` to the `statusLine` command and to nothing
else — no hook has ever seen those numbers. With no command wired, no usage is recorded,
and the frame's top row has no `ctx NN%` / `cache NN%` to draw.

It draws **nothing** rather than a confident `ctx 0%`, which is the rule that panel has
always kept: a gauge silently reading zero is worse than no gauge. Every part of the
recording path — `record_usage`, `_record_turn`, `recorded_context_gauge` — is untouched,
so wiring a `statusLine` back yourself brings the gauge back with it.

## What it does not cost: `charter reopen`

`charter reopen` resumes a Claude Code conversation by the harness session id charter wrote
down, and the `statusLine` command used to be the only writer of it. A hook holds the same
two ids for the same two reasons — it runs in the chat's own pane, so `$CHARTER_SESSION_ID`
is in its environment, and every hook payload carries `session_id` — so `sessionstart`
records the mapping now. Resume is unchanged, and slightly better: a chat abandoned before
its first prompt is recorded too, where the old writer needed a turn.
