version: 0.61.1
headline: `charter vault add --persona` refuses a name no persona here has, and `charter vault list` marks a registration whose persona is gone
---

`charter vault add devops --provider plain-file --persona devosp` used to report success. The
persona is only a label on the registration, so a misspelling, `../x` or a name of only
whitespace was stored as given. `charter persona secret` finds a vault by the persona name it
is tagged with, so no persona in the plane found that vault, and the mistake showed up later as
a failed secret read, often in another session.

Now `vault add` checks the name before it writes either half of the registry, with or without
`--force` and `--share`. It uses the sentences the persona commands already use:

```
✗ no persona 'devosp' (create it: charter persona create devosp)
✗ invalid persona name '../x' (lowercase letters, digits, '.', '_', '-')
✗ no persona ' ' (a persona name is never only whitespace)
```

A registration made before this, or one whose persona was removed afterwards, still lists.
`charter vault list` marks it on its row, as `ghost (no such persona)`, and still exits 0.

Nothing to adopt. If `vault list` marks a row, remove that registration with `charter vault
remove <name>` and add it again with a persona that exists
([#1057](https://github.com/diazoxide/charter/issues/1057)).
