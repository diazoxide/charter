version: 0.61.1
headline: `charter doctor` stops warning that the handoff rule is missing where charter wrote it into `.claude/settings.local.json`
---

`charter doctor`'s `handoff gate` row read only `.claude/settings.json`. Claude Code also honours
`.claude/settings.local.json`, and charter writes the rule there itself: `charter guard ask
--local` at the plane root, and `charter workspace reinit` into a checkout inside a workspace.
So right after either, the row warned that the rule was not in force and told you to add it
again with `charter guard ask`.

The row now counts the rule in the local file in the two places Claude Code reads it for a
session — the session's own directory and the git root, measured on 2.1.267. A workspace
directory inside the plane's repository is gated by the plane's local rule without a copy of its
own; outside a repository it is not, and the row still warns there. A local file charter cannot
parse or open is reported as not checked rather than read as holding the rule.

`charter guard ask` is unchanged: it still writes the shared rule you ask for, even where a local
one already exists.
