version: 0.61.1
headline: `charter workspace reinit` names a workspace's `refs/` symlink loop instead of crashing on it
---

A workspace whose own `refs/` is a symlink to itself took `charter workspace reinit` down with a
`FileExistsError`. Charter had already found the loop — it was on its way to saying so — and then
tried to create `refs/` over it, which a link that resolves to no directory refuses.

Reinit now writes nothing there, and says what it found and what clears it, in the words
`charter doctor` uses for the same path:

```
! 'north': refs/README.md cannot be checked — charter writes nothing there it cannot see; fix the symlink loop at …/workspaces/north/refs.
```

It names `refs/` itself rather than the README behind it, because `refs/` is the link: a loop
anywhere above a baseline file is now named where the loop is. The link is left exactly as it
was, and reinit exits 0, as it does for a `refs/` it may not read.
