headline: A chat opened in the background whose profile refused to start always says why, however fast it refused
---

When a handoff, a reopen or a background open starts a chat whose profile cannot run — its
command is not on `PATH`, say — the chat's pane refuses and records why, and the launch that
opened it repeats that sentence and exits with the refusal's own code (127 for a missing
command). If the pane had already refused and exited by the time charter first checked on it,
that record was skipped: the launch reported the command as having `exited 1 before the frame
was drawn` and the reason never reached you. This happened mostly on loaded Linux machines.
Charter now reads the record first, so a refused chat says why and exits with the right code
however quickly it refused.
