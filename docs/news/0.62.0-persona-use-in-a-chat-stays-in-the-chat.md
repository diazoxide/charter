---
version: 0.62.0
headline: `charter persona use` in a chat selects the persona for that chat, and no longer promises a choice no new chat will have
---

Inside a charter frame, `charter persona use ops` printed:

```
✓ Active persona set to 'ops' for this terminal (kept across closing/reopening Claude).
```

No new chat had that choice. And the terminal pointer written beside it was keyed on
something other than the chat, so it was read later by someone who never chose `ops`:

- **a tmux pane number.** tmux numbers panes per server, and charter's server exits with its
  last frame, so the next frame's chats draw `%0`, `%1`, … again. Measured: a chat on pane
  `%9` chose `ops`, and a chat on a later server that drew `%9` started as `ops`.
- **the launching terminal's `$TERM_SESSION_ID`.** A frame started from Terminal.app or
  iTerm2 outside tmux passes that variable to every pane on its server. Measured: another chat
  on the same server, and the shell the frame was launched from, both resolved `ops`.

Now, inside a chat, `persona use` and `persona create --use` write the chat's own session
pointer and no terminal pointer, and say what that means:

```
✓ Active persona set to 'ops' for this chat only — a new chat does not inherit it.
```

Every `charter` command run in the chat, by you or by an agent it spawns, still resolves
`ops`. The frame's persona column already selected this way, and `charter workspace use`
has since 0.61.0. Outside a chat nothing changes: a harness in an ordinary terminal pane
still keeps its persona across closing and reopening Claude.
