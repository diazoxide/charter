`docs/assets/frame.svg` stopped being a picture of charter with #904. Four things moved on
that surface and the capture kept showing the ones before them: a chat count drawn as
`(1)` in a six-cell field rather than ` 1 ` in a three-cell one, the tab after it three
columns right of where charter now puts it, and an active tab wearing reverse video with no
underline.

## Old is a different thing from wrong

Until #904 that capture was **old**. Everything in it was something charter had drawn, just
not lately, and the cost of that is a reader seeing an earlier charter than the one they
installed. From the moment #904 merged it was **wrong**: the strip in it is one charter will
not draw at any width, on any plane.

That distinction is the whole reason this is its own change rather than a line in a release
checklist. `docs/assets/README.md` states the contract — captures are *"generated from real
command output… none should ever be hand-edited — regenerate instead, so a screenshot cannot
quietly drift from what charter actually prints"* — and a contract like that invites a reader
to trust the picture exactly as far as real output deserves. A capture that is confidently
wrong spends trust the directory earned honestly.

So `frame.svg` is re-taken with `docs/assets/capture-frame.sh`, which is hermetic: its own
synthetic plane, its own tmux on its own socket, no network and no toolchain beyond a stdlib
venv. `social-card.svg` re-reads `frame.svg` whole, so the card followed rather than being
adjusted, and `social-card.png` re-rendered from the card. Nothing here was edited by hand,
which is the one rule this directory has.

## The three that were only old

`demo.svg`, `personas.svg` and `statusline.svg` are untouched by #904 and share nothing with
it but the stamp. They were re-taken anyway, because all four sat at `0.56.0` against a
`0.57.0` charter — already the one minor `tests/test_asset_freshness.py` allows, so `0.58.0`
reddens `TestTheCapturesAreNotStale` whether or not anything drifted. Regenerating is
deliberately a check rather than a release step, which means the bill can be paid at any
convenient moment and the only inconvenient moment is during a release.

**Two of them came back byte-identical, and that is worth reading correctly.** `demo.svg`
prints no version and no clock, and the org it queries still answers with the same repos;
`personas.svg` is one command's own output against a plane the script builds from scratch.
An identical file is evidence a capture is stable, not evidence one was skipped — the stamp
records the version a capture was last *confirmed* to match, which is a claim only a re-run
can make. `statusline.svg` moved, on the version in its own footer and on the relative times
the demo plane's heartbeats produce.

All four now read `0.57.0`, which is a minor of slack again: the next release goes out
without touching this directory, and the one after that says so if nobody has.
