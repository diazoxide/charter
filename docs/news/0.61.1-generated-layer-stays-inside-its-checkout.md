**Affected: every release through 0.61.0. Fixed here; the fix is the upgrade.**

Charter wires a harness layer (`.claude/settings.json`, mirrored agents and skills, and its
`.charter-generated` record) into the checkouts under a workspace. A checkout is committed
content charter did not write, so no path it supplies is trusted any more. Every write,
replacement, unlink and directory prune charter performs in a checkout or a workspace must
resolve inside that checkout, or charter refuses it and reports it as `blocked`. The
ownership record is read only when charter can vouch for it, and charter removes only files
under its own generated roots.

Ordinary checkouts are unaffected: the layer lands, is hidden in `info/exclude`, and is
reported as before. Where charter now refuses a path, `charter doctor` and the `reinit` /
`clone` output name it.

Details are in the security advisory published with this release.
